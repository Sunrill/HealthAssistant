# 智能健康助手 HealthAssistant

一个跑在自己电脑上的健康小助手。它能做四件事：

1. **记数据**——每天花十几秒记下体重、睡眠、步数、血压；
2. **读体检报告**——把体检 PDF 丢进去，自动整理出 60 多项指标，告诉你哪几项偏高；
3. **回答问题**——"我的尿酸高吗""为什么要少喝啤酒""多久复查一次"；
4. **一家人分开用**——每人一份档案，数据互不干扰。

所有数据都存在你自己的电脑里，不上传任何服务器。只有"组织语言"这一步会调用大模型 API。

> 这不是医疗工具。它不会诊断疾病，也不会告诉你吃什么药。所有结论都需要医生确认。

## 开始之前

**你需要三样东西：**

| 需要 | 说明 |
|---|---|
| 一台 Windows 电脑 | 本教程在 Windows 10/11 + WSL2 上验证过 |
| 一个模型 API key | DeepSeek、智谱、ModelScope 任选一个，注册后通常有免费额度 |
| 30 分钟 | 第一次安装依赖占大部分时间 |

**你会用到两个窗口：**

- **PowerShell**（Windows 自带）——提示符长这样：`PS C:\Users\你的名字>`
- **Ubuntu 终端**——提示符长这样：`你的名字@电脑名:~$`

后面所有命令我都会标明该在哪一个里敲。搞不清楚的时候，看提示符就行。

---

## 第 0 步：装好 WSL 和 Ubuntu

如果你已经能用 `wsl` 命令进 Ubuntu，跳过这一步。

**在 PowerShell 里执行：**

```powershell
wsl --install -d Ubuntu-24.04
```

装完会让你创建 Linux 用户名和密码（和 Windows 账号没关系，随便取）。密码输入时不显示，是正常的。

**验证：** 在 PowerShell 里执行 `wsl -l -v`，看到这样就算成功：

```
  NAME            STATE           VERSION
* Ubuntu-24.04    Running         2
```

> `VERSION` 必须是 2。如果是 1，执行 `wsl --set-version Ubuntu-24.04 2`。

**以后怎么进 Ubuntu：** 打开 PowerShell，输入 `wsl` 回车。提示符变成 `名字@电脑:~$` 就进去了。

## 第 1 步：拿到项目并安装依赖

**在 Ubuntu 终端里执行**（后面都简称"终端"）：

```bash
cd ~
git clone https://github.com/shoxar/HealthAssistant.git
cd shoxar-HealthAssistant
```

没有 git 的话先装：`sudo apt install -y git`。

**安装依赖：**

```bash
uv sync
```

> `uv` 是 Python 的包管理工具，相当于更快的 pip。没装过的话执行：
> `curl -LsSf https://astral.sh/uv/install.sh | sh`
> 如果卡住不动，用国内源装：`pip install uv -i https://pypi.tuna.tsinghua.edu.cn/simple`

**建知识库索引：**

```bash
uv run python -m scripts.build_rag_index
```

**你应该看到：**

```
语料文件: 5 个
  aerobic-exercise: 4 块
  blood-pressure: 4 块
  fatty-liver: 4 块
  sleep: 3 块
  uric-acid: 4 块
切块总数: 19
索引已写入: .../data/knowledge/rag_index.json
```

这一步是给"本地资料"建目录。不建的话，第 9 步问健康常识会答不上来。

## 第 2 步：填一张钥匙卡

程序要调用大模型，需要你的 API key。这些信息放在项目根目录的 `.env` 文件里。

**复制模板：**

```bash
cp .env.example .env
```

**编辑它：**

```bash
nano .env
```

把内容改成你自己的（下面以 DeepSeek 为例）：

```ini
LLM_MODEL_ID=deepseek-chat
LLM_API_KEY=sk-你的真实密钥
LLM_BASE_URL=https://api.deepseek.com/v1
LLM_TIMEOUT=60
```

改完按 `Ctrl+O` 保存，回车确认，再按 `Ctrl+X` 退出。

**每一行是什么意思：**

| 字段 | 填什么 | 去哪找 |
|---|---|---|
| `LLM_MODEL_ID` | 模型名字 | 用哪个服务就填哪个，见下表 |
| `LLM_API_KEY` | 你的密钥 | 服务商后台的 "API Keys" 页面 |
| `LLM_BASE_URL` | 服务地址 | 见下表，**结尾的 `/v1` 不能少** |
| `LLM_TIMEOUT` | 超时秒数 | 保持 60 即可 |

**三家服务怎么填：**

| 服务 | `LLM_MODEL_ID` | `LLM_BASE_URL` |
|---|---|---|
| DeepSeek | `deepseek-chat` | `https://api.deepseek.com/v1` |
| 智谱 | `glm-4-plus` | `https://open.bigmodel.cn/api/paas/v4` |
| ModelScope | `Qwen/Qwen2.5-72B-Instruct` | `https://api-inference.modelscope.cn/v1/` |

**验证一下通不通：**

```bash
uv run python scripts/check_llm.py
```

**你应该看到**类似这样的一句回答：

```
MODEL: deepseek-chat
RESPONSE: 我是一个人工智能助手……
```

**如果报错：**

| 报错 | 原因 | 怎么办 |
|---|---|---|
| `必须提供模型名称` | `.env` 没被读到 | 确认当前目录是项目根目录，再 `cat .env` 看看内容在不在 |
| `401 Unauthorized` | key 错了 | 回服务商后台重新复制，注意别带空格 |
| `404 Not Found` | 地址写错 | 检查结尾有没有 `/v1` |
| 一直转圈 | 网络问题 | 见[常见问题](#常见问题)最后一条 |

## 第 3 步：第一次启动

```bash
uv run python main.py
```

**你应该看到：**

```
✅ 工具 'profile' 已注册。
……
健康助手已启动。输入 /help 查看命令，exit 退出。
当前成员：（未指定）

你 >
```

看到 `你 >` 就是成功了。这个提示符代表"程序在等你说"，和终端的 `$` 不一样——**看到 `$` 说明你还在外面，命令没进程序**。

这一屏里能敲两类东西：

- 直接说人话，比如 `我男 24 岁，身高 180，体重 85`（模型处理）
- 斜杠开头的命令，比如 `/help`、`/add`、`/use`（程序处理）

**退出**：输入 `exit` 回车。

---

## 第 4 步：给自己建档案

第一次用，先建成员，再录档案。**在 `你 >` 后面依次输入：**

```
/add 我 本人
```

**你应该看到：**

```
已建立并切换到：我（本人）
```

然后录基础信息：

```
男 24 岁，身高 180，体重 85，平时久坐
```

**你应该看到**类似：

```
助手 > 档案已保存：我，male，24岁，180.0cm，85.0kg
```

**为什么要这一步：** 算 BMI 必须有身高体重，算每日消耗还要年龄性别。没有档案，后面的数值都算不出来。

活动量可以这样说：`久坐` / `轻度活动` / `每周运动三四次` / `高强度训练`。

---

## 第 5 步：记录今天的数据

接着输入：

```
今天睡了 6.5 小时，走了 8000 步，血压 126/76
```

**你应该看到**确认保存的回复。

没提到的那几项（体重、饮水）可以下次再补。同一天重复说会覆盖，不会产生两条。

现在可以问它算得对不对：

```
我的 BMI 是多少，血压正常吗
```

**你应该看到**类似：

```
助手 > 你的 BMI 是 26.2，属于超重；血压 126/76 属于正常高值……
```

**这里要留意一件事：** BMI 这个数字必须来自程序计算，而不是模型"估"的。同样的身高体重每次算出来都应该是 26.2。如果它给了 26 或 26.3，说明哪里不对。

## 第 6 步：导入体检报告

**先退出程序**（输入 `exit`），回到终端。

**把 PDF 放进项目：**

```bash
mkdir -p data/reports
cp "/mnt/c/Users/你的Windows用户名/Desktop/体检报告.pdf" data/reports/checkup.pdf
```

> `/mnt/c/` 就是 Windows 的 C 盘。桌面文件在 `/mnt/c/Users/你的名字/Desktop/`。

**开始解析：**

```bash
uv run python -m scripts.parse_report data/reports/checkup.pdf 2026-10-01
```

最后的 `2026-10-01` 是报告日期，填你体检那天的日期（格式必须是 `年-月-日`）。

**你应该看到：**

```
报告期间: 2026 年 10 月
指标总数: 61
  (未分组): 5
  血常规: 24
  肝功能: 11
  肾功能: 3
  血脂: 4
  血糖: 1
  糖化: 1
  尿常规: 12
异常项: 3
  淋巴细胞绝对值 = 3.82 ×10^9/L (参考 1.1–3.2，偏离 19.4%，中度)
  血小板分布宽度 = 17.0 % (参考 9.8–16.2，偏离 4.9%，轻度)
  尿酸 = 480.0 μmol/L (参考 208.0–428.0，偏离 12.1%，中度)
结论条数: 9
已保存到 .../data/members/m1/lab/
```

数字不一定和上面完全一样，取决于你的报告。

**如果解析出 0 项：** 大概率是扫描件（整页图片，没有文字层）。目前只支持电子版 PDF。

**如果是家人的报告**，加 `--member` 指定给谁：

```bash
uv run python -m scripts.parse_report data/reports/baba.pdf 2026-08-15 --member m2
```

## 第 7 步：问报告里的问题

重新启动：

```bash
uv run python main.py
```

依次问这几句：

```
我 2026 年 10 月的体检有什么问题
尿酸 480 严重吗，什么时候复查
我该挂哪些科
```

**能答的：** 哪几项偏高、偏高多少、参考范围是多少、建议什么时候复查、挂什么科。

**答不了的（这是故意的）：**

```
我的眼底报告写着杯盘比大，是不是青光眼
```

它只会说"需要眼科面诊，需结合眼压和 OCT 检查"，**不会**给你下结论。影像类结论必须由医生判断，这是刻意设计的边界。

## 第 8 步：给家人建档

在 `你 >` 后面：

```
/add 爸爸 父亲
男 62 岁，身高 172，体重 78，平时久坐
```

然后切回来：

```
/use 我
```

**查看所有人：**

```
/members
```

**你应该看到：**

```
  * 我（本人）
    爸爸（父亲）
```

`*` 表示当前在用谁。**给谁操作之前先 `/use 谁`**，否则数据会记到别人名下。每人可以有自己的报告和记录，互相看不到。

## 第 9 步：问健康常识

```
为什么尿酸高要少喝啤酒
```

它会在本地资料里查，然后引用出处回答（"据本地资料《尿酸与高嘌呤饮食》"）。

再试两个：

```
超重的人适合做什么运动
脂肪肝多久复查一次
```

**再试试它不知道的：**

```
跑步机坡度多少合适
```

**正确表现**是承认"本地资料没有覆盖"，而不是硬编一个答案。本地资料只有 5 个主题：尿酸、脂肪肝、血压、有氧运动、睡眠。

## 项目文件都是干什么的

看不懂代码也没关系，这一节告诉你"想改哪里该去哪个文件"。

```
shoxar-HealthAssistant/
├── main.py                  ← 程序入口，负责跟你对话
├── src/
│   ├── agent.py             ← 告诉 AI"你是谁、能做什么、什么不能说"
│   ├── tools.py             ← 4 个日常功能（建档、记数据、算指标、看趋势）
│   ├── metrics.py           ← 数学计算：BMI、代谢、血压分级
│   ├── models.py            ← 数据长什么样
│   ├── storage.py           ← 存到硬盘、从硬盘读
│   ├── report.py            ← 生成周报
│   ├── lab/                 ← 体检报告相关（解析、判定、复查、趋势）
│   └── rag/                 ← 健康常识检索（本地资料）
├── scripts/
│   ├── parse_report.py      ← 手动导入报告的命令
│   ├── build_rag_index.py   ← 建资料索引
│   └── check_llm.py         ← 检查 API 通不通
├── tests/                   ← 自动测试
├── docs/                    ← 扩展文档
└── data/
    ├── knowledge/corpus/    ← 健康常识原始资料（5 篇）
    ├── sample/              ← 示例报告
    ├── members/             ← 每个人的数据（不提交）
    └── reports/             ← 你的原始 PDF（不提交）
```

**想改健康常识** → 编辑 `data/knowledge/corpus/` 下的 md，改完重新跑 `build_rag_index`。

**想改 AI 的说话方式或禁忌** → 编辑 `src/agent.py` 里的 `SYSTEM_PROMPT`。

**想改 BMI 判定标准** → 编辑 `src/metrics.py`。

## 常见问题

| 问题 | 原因 | 怎么办 |
|---|---|---|
| `uv: command not found` | 没装 uv 或没加进 PATH | `echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.bashrc && source ~/.bashrc` |
| `ModuleNotFoundError: src` | 用了 `python scripts/xxx.py` | 改成 `uv run python -m scripts.xxx`（加 `-m`） |
| `/use` 提示 No such file | 在终端敲了程序内的命令 | 先 `uv run python main.py`，看到 `你 >` 再敲 |
| `必须提供模型名称` | `.env` 没读到 | 确认在项目根目录执行；`cat .env` 检查内容 |
| 解析出 0 项指标 | PDF 是扫描件 | 需要可复制的电子版 PDF |
| 问常识说"没有覆盖" | 该主题不在 5 篇资料里 | 正常行为，可自行往 `corpus/` 加资料 |
| 周报里没有体检内容 | 功能未实现 | 见"目前还做不到的事" |
| `pytest` 命令失败 | 没装测试依赖 | `uv add --dev pytest` |

**关于网络超时：** 如果 Windows 上开了代理软件，WSL 里可能用不了。两个办法：

1. 在终端里临时设置（每次重开都要设）：
   ```bash
   export https_proxy=http://$(ip route show default | awk '{print $3}'):7890
   ```
   端口换成你代理软件的实际端口。

2. 或者关掉代理，DeepSeek 等国内服务一般可以直连。

## 数据与隐私

**数据存在哪：**

```
data/members/m1/profile.json   ← 你的档案
data/members/m1/records.json   ← 每日记录
data/members/m1/lab/*.json     ← 体检指标
```

就是几个 JSON 文件，记事本也能打开。

**哪些不会上传 GitHub：**

| 目录 | 内容 | 是否提交 |
|---|---|---|
| `data/members/` | 你和家人的健康数据 | ❌ 不提交 |
| `data/reports/` | 原始体检 PDF | ❌ 不提交 |
| `.env` | 你的 API key | ❌ 不提交 |
| `data/knowledge/corpus/` | 健康常识资料 | ✅ 提交 |
| `data/sample/` | 示例报告（编造的） | ✅ 提交 |

**除了调用大模型，数据不离开你的电脑。** 也就是说：你问的这句话、以及工具查到的相关内容，会发送给模型服务商。如果对此有顾虑，可以换成本地模型（如 Ollama），改 `.env` 里的 `LLM_BASE_URL` 即可。

**发布前自检：**

```bash
git check-ignore -v data/members/m1/profile.json data/reports/checkup.pdf .env
```

输出三行说明这三样都被正确忽略了。少于三行就先别提交。

## 目前还做不到的事

写清楚这些，避免你把"没做"当成"坏了"：

| 限制 | 说明 |
|---|---|
| 周报不含体检内容 | 周报只读日常记录 |
| 复查提醒只覆盖化验项 | "眼科就诊""脂肪肝复查"这类文字结论没进提醒 |
| 只支持一种报告版式 | 换医院可能需要调整解析规则 |
| 只支持电子版 PDF | 扫描件需要 OCR |
| 不能手动添加单项指标 | 只能整份导入 |
| 知识库只有 5 个主题 | 超出范围会说"没有覆盖" |

## 想深入看代码

如果你是开发者，这几处值得看：

- **`src/agent.py`**——整个项目只有这个文件调用大模型。所有"什么能说、什么不能说"的约束都在那段提示词里。
- **`src/metrics.py`、`src/lab/rules.py`**——全是纯函数（同样输入必得同样输出），所以能写测试。24 条测试主要覆盖这两处。
- **`src/rag/`**——用 BM25 检索，没有用向量库。因为资料只有 19 个片段，BM25 够用且零依赖。想升级成向量检索，见 `docs/rag-implementation-steps.md`。

**跑测试：**

```bash
uv run pytest -q
```

预期 `24 passed`。
